# Standards implemented

This project implements the following [standards](https://gitea.crzynet.com/crzynet/homelab-configs/src/branch/main/standards)
from the crzynet `homelab-configs` repo. Each row pins the **version** that this
project has actually wired up. Bumping a pin is a deliberate act (re-implement against
the new revision in the same commit that updates the pin); standards do not auto-upgrade
adopters.

| Standard | Version | Adopted | Notes |
|---|---|---|---|
| [handoff-prompt-workflow](https://gitea.crzynet.com/crzynet/homelab-configs/src/branch/main/standards/handoff-prompt-workflow/README.md) | 2.0.0 | 2026-08-11 | **Fully wired at v2.0.0.** `prompts/TEMPLATE.md` copied byte-identical from the standard; `prompts/done/` and `prompts/failed/` created lazily on first use per the standard. `CLAUDE-snippet.md` pasted **verbatim** into `CLAUDE.md` as "Handoff prompts (operational rules)", carrying the v2.0.0 per-session default (any >1–2-file edit becomes a `prompts/` file executed by a **spawned subagent**). `CLAUDE.md` points here per the cross-cutting [How standards reach Claude](https://gitea.crzynet.com/crzynet/homelab-configs/src/branch/main/standards/README.md#how-standards-reach-claude) rule. `docs/decisions.md` created. **One documented deviation:** the adoption commit itself was done in-session rather than via a handoff prompt — the prompt would have had to live in the `prompts/` dir it was creating, inside a git repo that did not yet exist, with no working tree for the mandated `git status --porcelain` check. Every task after it goes through the workflow. See `docs/decisions.md` (2026-08-11). Because `code-checkin-and-pr` is not adopted, the standard's step-6 fallback applies: plain one-line commit messages on the current branch, no branch or prefix requirement imposed by this workflow. |
| [code-checkin-and-pr](https://gitea.crzynet.com/crzynet/homelab-configs/src/branch/main/standards/code-checkin-and-pr/README.md) | — (not adopted) | — | **Deliberately deferred until the first GitHub push.** Every rule the standard carries presupposes a remote: `main` branch protection, `dev → main` PRs, 7 required CI checks (lint / config validation / migration-to-head / compose validation / image build / test suite / SAST), image publishing and registry retention. This repo has no remote and no CI, so claiming adoption would be a row that lies. Two of its conventions are followed **voluntarily** from commit one so the history is already conformant at adoption time: Conventional-Commit prefixes (`feat:` / `fix:` / `chore:` / `docs:`) and no `Co-authored-by:` trailers. Branch shape also matches (`dev` for day-to-day, `main` untouched). Adopt properly — and re-pin this row at the then-current version — in the same change that adds the remote and CI. |
