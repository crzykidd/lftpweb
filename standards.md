# Standards implemented

This project implements the following [standards](https://gitea.crzynet.com/crzynet/homelab-configs/src/branch/main/standards)
from the crzynet `homelab-configs` repo. Each row pins the **version** that this
project has actually wired up. Bumping a pin is a deliberate act (re-implement against
the new revision in the same commit that updates the pin); standards do not auto-upgrade
adopters.

| Standard | Version | Adopted | Notes |
|---|---|---|---|
| [code-checkin-and-pr](https://gitea.crzynet.com/crzynet/homelab-configs/src/branch/main/standards/code-checkin-and-pr/README.md) | 1.2.0 | 2026-08-11 | **Fully live.** Wired ahead of the first GitHub push, then completed by it — the repo now exists at [crzykidd/lftpweb](https://github.com/crzykidd/lftpweb) and [`docs/repo-setup.md`](docs/repo-setup.md) is the historical runbook, not a checklist to re-run. `.github/workflows/ci.yml` implements 6 of the 7 required checks as separately-named jobs (GitHub binds required-status-checks to the bare job `name:`, not `workflow / job` — see the in-file comment): **Backend lint** (`ruff check` + `ruff format --check`, config in a new root [`ruff.toml`](ruff.toml) — kept out of `pyproject.toml` deliberately, see the file's own header comment), **Frontend lint + typecheck** (`npm run lint` = oxlint, `npm run build` = `tsc -b && vite build`), **Config validation** (every checked-in YAML/JSON parses), **Compose validation** (`docker compose config --quiet` on all three compose files), **Image build** (PR-only, `docker/Dockerfile`'s `runtime` target, no push), and **Test suite** (`uv run pytest`) — the 7th, **SAST**, is GitHub's CodeQL *default setup* (`python` + `javascript-typescript`), which is a repo setting, not a workflow file, enabled per the runbook. **Migration → head is not a separate CI job**: it's already covered by `tests/test_db.py`, which the Test-suite job runs as part of `uv run pytest`. The **Test suite** job explicitly brings up `docker-compose.test.yml` (running `docker/test-seedbox/gen_key.sh` first) and waits for both fake-seedbox ports before running pytest, then greps the run for the seedbox-unreachable skip reason and fails the job if found — this exists specifically so `tests/test_queue.py` and the phase-2 seedbox-gated tests in `tests/test_remote.py` cannot silently skip in CI; a green run that skipped them would be worse than no CI. `.github/workflows/publish.yml` implements the image-publishing matrix (`:dev`+`:sha-<short>` on push to `dev`; `:latest`+`:sha-<short>` on push to `main`; `:latest`+`:<semver>`+`:<major>` on `release: published`) against `ghcr.io/crzykidd/lftpweb` — fixed `docker-compose.yml`'s `image:` from a stale `ghcr.io/crzynet/...` to the correct `ghcr.io/crzykidd/...` owner as part of this adoption. `.github/workflows/retention.yml` implements registry retention (keep 30 most recent `:sha-*`, keep 15 most recent semver, `:latest`/`:dev`/bare-major protected). `CLAUDE-snippet.md` pasted **verbatim** into `CLAUDE.md` as "Code check-in (operational rules)", replacing the old "not adopted" paragraph. **Honest gaps, left for the code owner (not fixed by this adoption — see the 2026-08-11 adoption report):** `ruff check` currently reports one real violation (`backend/lftpweb/api/settings.py:15`, unused `RemoteScanError` import) and `ruff format --check` reports ~22 files that predate this config and were never run through `ruff format`. Both made the **Backend lint** job red on the very first CI run; **both are since fixed** (the unused import removed, every file run through `ruff format`) and both lint gates have been clean for every phase from 3b onward. **Branch protection on `main` is live and verified** (`gh api repos/crzykidd/lftpweb/branches/main/protection`, re-checked at phase 9): 8 required status checks (the 6 CI jobs plus CodeQL for both languages), PR required, force-push and deletion blocked, admin bypass retained. |
